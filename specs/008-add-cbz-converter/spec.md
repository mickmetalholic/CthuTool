# Feature Specification: 漫画格式转换工具

**Feature Branch**: `008-add-cbz-converter`  
**Created**: 2026-04-17  
**Status**: Draft  
**Input**: User description: "在 @cthutool/cli 中新增可由 scripts 命令运行的批量 PDF/ePub 转 CBZ 工具"

## Clarifications

### Session 2026-04-17

- Q: 不同子目录下同名源文件如何避免输出冲突？ → A: 在输出目录中保留源文件的相对目录结构。
- Q: 图片质量配置如何避免“自动选择”歧义？ → A: 明确为可配置且有默认值。

### Session 2026-04-22

- Q: 当前文件进度条是否应持续展示已完成文件？ → A: 仅展示当前活跃转换文件的进度，文件完成后不再展示其进度条。
- Q: 进度条后方的文件标识应显示什么？ → A: 显示相对路径，不显示全路径。
- Q: 最终总结输出的展示风格与语言应如何约束？ → A: 使用英文总结，采用美观排版，可使用 emoji，并用多种颜色区分不同状态信息。
- Q: 全局进度条与当前文件进度条如何视觉区分？ → A: 两类进度条必须使用不同颜色显示，以便用户快速区分总体进度与当前文件进度。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 批量发现并转换漫画文件 (Priority: P1)

作为用户，我希望指定一个目录后，工具自动扫描该目录及其子目录内的 PDF/ePub 漫画文件，并批量转换为 CBZ，以便一次完成大量文件处理。

**Why this priority**: 这是功能核心价值，若无法批量发现与转换，工具无法满足主要使用场景。

**Independent Test**: 在含有多份 PDF/ePub 文件的目录运行命令，验证工具可发现全部目标文件并逐一生成对应 CBZ。

**Acceptance Scenarios**:

1. **Given** 用户通过命令参数提供有效目录，**When** 启动转换任务，**Then** 系统扫描该目录及所有子目录并识别全部 `.pdf` 与 `.epub` 文件。
2. **Given** 扫描结果包含多个可处理文件，**When** 批量任务执行完成，**Then** 每个成功文件都生成一个同名 `.cbz` 输出文件。

---

### User Story 2 - 获得清晰进度与结果反馈 (Priority: P2)

作为用户，我希望在转换过程中看到总体进度和当前文件内部进度，并在结束后得到清晰总结报告，以便判断任务状态与后续处理动作。

**Why this priority**: 转换任务可能耗时较长，缺乏进度与总结会显著降低可用性与可控性。

**Independent Test**: 执行至少 3 个文件的批量转换，验证过程输出包含两层进度与状态分类，结束后输出统计结果、失败清单、输出目录与总耗时。

**Acceptance Scenarios**:

1. **Given** 批量任务正在执行，**When** 任意时刻查看终端输出，**Then** 可以同时看到已处理文件数/总文件数与当前活跃文件的已处理页数/总页数；全局进度条与当前文件进度条使用不同颜色区分；当前文件进度条后方显示相对路径（不显示全路径），且已完成文件不再保留其进度条展示。
2. **Given** 全部任务结束，**When** 查看终端总结，**Then** 用户可看到英文的结构化总结（美观排版，可含 emoji），并包含成功数、失败文件及原因、输出目录和总耗时，且不同状态信息使用多种颜色区分。

---

### User Story 3 - 单文件失败不影响全局任务 (Priority: P3)

作为用户，我希望当某个文件损坏、受保护或格式异常时，系统跳过该文件并继续后续文件，而不是中断整个批处理。

**Why this priority**: 现实文件集合常包含异常项，容错能力直接影响任务完成率。

**Independent Test**: 在混合输入中加入至少 1 个不可转换文件，验证系统记录失败原因并继续处理其余文件。

**Acceptance Scenarios**:

1. **Given** 批量列表中有不可转换文件，**When** 处理该文件时报错，**Then** 系统记录失败并继续处理下一个文件。
2. **Given** 遇到读写权限不足，**When** 系统访问受限路径，**Then** 系统输出清晰可理解的权限错误提示并保持其余可处理文件继续执行。

### Edge Cases

- 用户未提供目录参数时，系统应主动发起交互式提问并接收输入路径。
- 用户提供的路径不存在或不是目录时，系统应立即提示并终止，不进入扫描阶段。
- 目录扫描完成后未发现任何 `.pdf` 或 `.epub` 文件时，系统应提示“无可转换文件”并结束。
- 某文件输出目标不可写（例如 `.output` 无权限）时，应将该文件记为失败并继续其他文件。
- 同名源文件位于不同子目录时，输出目录必须保留源文件相对目录结构，以避免覆盖并保持一一映射。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持用户通过命令参数指定待处理根目录。
- **FR-002**: 当命令参数未提供目录时，系统必须通过交互式流程要求用户输入目录路径。
- **FR-003**: 系统必须校验输入路径存在且为目录；校验失败时必须明确提示并终止任务。
- **FR-004**: 系统必须递归扫描指定目录与全部子目录，并识别扩展名为 `.pdf` 与 `.epub` 的文件（大小写不敏感）。
- **FR-005**: 当扫描结果为空时，系统必须输出无目标文件提示并结束，不进入转换流程。
- **FR-006**: 系统必须逐个处理扫描结果中的文件，并将每个源文件转换为独立 CBZ 输出。
- **FR-007**: 对于 PDF 输入，系统必须将每一页转换为一张高质量图片；默认渲染分辨率不得低于 200 DPI（或等效像素密度），且当页面包含文字时，正文在 100% 缩放下应保持可读。
- **FR-008**: 对于 ePub 输入，系统必须按原始阅读顺序提取内容页图片；原始阅读顺序定义为优先采用 OPF spine 顺序，若缺失则回退到导航文档顺序，再回退到包内文档稳定字典序，确保 CBZ 内页序与源阅读顺序一致。
- **FR-009**: 系统必须将单个源文件产生的图片按阅读顺序重命名为连续序号，并使用前导零（例如 `001`, `002`, `010`）。
- **FR-010**: 系统必须为每个源文件生成同名 `.cbz` 文件（仅扩展名变化），并将输出写入与用户输入路径对应的 `.output` 目录。
- **FR-011**: 系统必须在 `.output` 中保留源文件相对目录结构；同名文件位于不同子目录时，必须输出到各自对应的相对路径下，禁止覆盖。
- **FR-012**: 系统必须允许用户显式配置输出图片格式与压缩质量，并在未提供配置时使用预定义默认值；允许格式为 `jpg` 或 `png`，质量参数取值范围为 `1-100`（仅 `jpg` 生效），默认值为 `jpg` + `85`。
- **FR-013**: 任一文件转换失败时，系统必须记录失败状态与原因，跳过并继续后续文件，不得中断整个批处理。
- **FR-014**: 系统必须在运行中提供两层进度反馈：总体文件进度与当前活跃文件页进度；总体进度条与当前文件进度条必须使用不同颜色以便区分；当前文件进度条后方必须显示源文件相对路径（不显示全路径）；文件转换完成后必须从当前文件进度展示中移除，不再持续显示已完成文件的进度条。
- **FR-015**: 系统必须使用可区分的颜色或符号呈现信息、成功、警告、失败等状态；最终总结阶段必须使用多种颜色区分不同状态信息。
- **FR-016**: 全部任务结束后，系统必须输出英文总结报告，采用结构化且美观的终端排版（可包含 emoji）；报告至少包含成功数量、失败文件列表及原因、输出目录、总耗时；失败文件列表必须为每条失败记录提供源文件相对路径、失败阶段（扫描/读取/转换/写入/打包）、用户可读原因。
- **FR-017**: 当发生读权限或写权限问题时，系统必须输出清晰、可操作的错误提示。

### Key Entities *(include if feature involves data)*

- **Conversion Job**: 一次批量转换任务，包含输入根目录、开始/结束时间、总文件数、成功数、失败数、输出目录。
- **Source Comic File**: 被扫描到的单个源文件，属性包含文件路径、文件类型（PDF/ePub）、可读性状态、处理结果。
- **Page Asset**: 从单个源文件提取出的有序图片页，属性包含页序号、命名结果、格式、压缩质量。
- **Failure Record**: 单文件失败记录，包含源文件标识、失败阶段、用户可读错误原因。

## Non-Functional Requirements

- **NFR-001 (Scale)**: 对于 100 个目标文件（每个文件不超过 300 页）的批任务，系统必须在 60 秒内完成扫描并开始第一个文件转换。
- **NFR-002 (Resource)**: 系统在单文件转换期间的峰值内存占用应保持在 1.5 GB 以下，并在单文件完成后释放临时资源。
- **NFR-003 (Filesystem Compatibility)**: 系统必须支持 Unicode 路径，并对保留字符或超长路径导致的目标文件名不可写情况给出可操作提示。
- **NFR-004 (Terminal Accessibility)**: 状态输出必须同时提供文字标签与符号，不得仅依赖颜色区分状态。

## Assumptions

- 默认输出目录按用户输入根目录创建为 `.output`，若不存在则自动创建。
- 输出质量默认采用 `jpg` + `85`，优先保证阅读清晰度并兼顾文件体积。
- 任务以本地单次执行为单位，不要求跨执行持久化任务状态。
- 若输入中存在嵌套极深目录，系统仍以完整递归为准，不对层级深度做业务限制。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含 100 个目标文件的目录中，用户可通过一次命令在 60 秒内完成全量扫描并开始第一个文件转换，无需逐文件操作。
- **SC-002**: 对于成功转换的文件，100% 产物可在常见 CBZ 阅读器中按正确页序连续阅读。
- **SC-003**: 当批处理中存在异常文件时，至少 95% 的可转换文件仍可在同一任务中完成转换（不因单文件失败中断）；可转换文件定义为“可读、未加密、格式有效且输出路径可写”的输入文件。
- **SC-004**: 任务结束后，在不滚动历史输出超过 3 屏的前提下，用户可在 30 秒内从总结报告中明确识别成功总数、失败原因与输出目录。

## Requirement-to-Scenario Traceability

- **TR-001**: 用户故事 1 验收场景覆盖 `FR-001` 至 `FR-011`。
- **TR-002**: 用户故事 2 验收场景覆盖 `FR-012`、`FR-014`、`FR-015`、`FR-016`。
- **TR-003**: 用户故事 3 验收场景覆盖 `FR-013`、`FR-017`。
- **TR-004**: `NFR-001` 到 `NFR-004` 由 quickstart 场景中的批量样本、异常路径样本与可访问性输出样本验证。

## Constitution alignment *(implementation)*

本规格聚焦用户价值与可验证行为，不限定具体库或实现细节。后续实现应遵循仓库宪章中关于模块化、质量门禁、错误处理与测试流程的约束。
