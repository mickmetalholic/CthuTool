# CLI 合同：convert-to-cbz

## 命令入口

- **命令组**: `cthutool scripts`
- **子命令**: `convert-to-cbz`
- **脚本包位置**: `apps/cli/src/scripts/convert-to-cbz`
- **分发入口**: `apps/cli/src/command/run-scripts.command.ts` 负责将 `scripts` 子命令分发到脚本包入口
- **脚本包契约**:
  - `script.json`: 脚本元信息（`id`、`title`、`description`）
  - `index.ts`: 默认导出 `run` 函数，作为脚本执行入口

## 启动预检合同（新增）

- 在开始扫描和转换前，必须执行 `checkDependencies()`。
- 必须检查以下命令可用且返回码为 `0`：
  - `pdftoppm -v`
  - `pdfinfo -v`
- 任一检查失败时必须立即终止流程（退出码 `1`），不得进入任务队列。
- 错误提示必须按平台给出安装指引：
  - `darwin`: `brew install poppler`
  - `linux`（Debian/Ubuntu）: `sudo apt-get install poppler-utils`
  - `win32`: `choco install poppler`，并提示可从 <https://github.com/oschwartz10612/poppler-windows/releases/> 下载并配置 `PATH`

## 参数合同

### 输入参数

- `--input <dir>`
  - 类型：`string`
  - 含义：待扫描根目录
  - 规则：可选；缺省时触发交互输入（FR-002）

- `--output <dir>`
  - 类型：`string`
  - 含义：输出根目录
  - 规则：可选；默认 `<input>/.output`（FR-010）

- `--format <png|jpg|webp>`
  - 类型：`enum`
  - 含义：输出图片格式
  - 规则：可选；有默认值（FR-012）

- `--quality <1-100>`
  - 类型：`number`
  - 含义：压缩质量（有损格式生效）
  - 规则：可选；范围校验失败则终止并提示（FR-003/FR-012）

- `--concurrency <n>`
  - 类型：`number`
  - 含义：文件级并发数
  - 规则：可选；最小值 1

- `--dpi <n>`
  - 类型：`number`
  - 含义：PDF 转图分辨率（传递给 `pdftoppm -r`）
  - 规则：可选；必须先校验为合法数值范围后方可参与命令执行

## 交互合同

当 `--input` 缺失时，CLI 必须提示用户输入目录路径：

- 提示文案：`请输入待转换目录路径`
- 若输入无效（不存在或非目录）：
  - 输出错误：`输入路径无效：路径不存在或不是目录`
  - 退出码：`1`

## 输出合同

### 过程输出

- 必须展示两层进度：
  - 总体进度：`已处理文件数 / 总文件数`
  - 活跃文件进度：同时展示多个并发执行文件的 `当前页(或章节) / 总页(或章节)`（FR-014）
- 日志级别至少包含：`info`, `success`, `warn`, `error`（FR-015）

#### 并发进度展示约束（新增）

- 子进度条数量必须与 `--concurrency` 生效值一致（上限可由实现安全阈值约束）。
- 每个子进度条需包含文件标识，且必须显示源文件相对路径（不得显示绝对路径）。
- 任务完成后，子进度条槽位可复用给下一个等待任务，但总体进度必须单调递增。
- 当终端宽度不足时，可对文件名做中间截断，不得隐藏进度数值。
- 必须优先复用现有进度组件（`cli-progress` `MultiBar`）；禁止引入并行的自定义光标控制渲染逻辑。
- 进度条运行期间，业务日志不得直接写入标准输出打断 UI；必须通过日志缓冲、统一 logger 队列，或在刷新间隔中安全落盘/落行。
- 全局进度条与当前文件进度条必须使用不同颜色，以便用户快速区分。

#### PDF 文件进度策略（新增）

- 先调用 `pdfinfo` 获取页数并设置该文件进度条总量。
- 再一次性调用 `pdftoppm` 转换全部页面，执行期间必须保持该文件进度条稳定可见（不使用 spinner），并显示“处理中”状态文案。
- `pdftoppm` 成功退出后，直接将该文件进度更新到总页数。
- 禁止逐页调用 `pdftoppm` 作为默认实现。

### 结果输出

任务结束后必须输出：

- 成功数量
- 失败文件列表（路径 + 原因）
- 输出目录
- 总耗时（FR-016）
- 英文总结文案，采用结构化且美观的终端排版（可使用 emoji）
- 对成功/失败/警告/提示等状态使用多种颜色区分

## 错误合同

- 文件级错误：记录失败并继续后续文件（FR-013）
- 路径/权限错误：提供可操作提示（FR-017）
- 无可转换文件：输出“无可转换文件”并正常结束（FR-005）
- 依赖预检错误：提供分平台安装指引并立即终止（不进入批处理）

## 安全执行合同（新增）

- 外部命令执行必须安全处理参数：
  - 文件路径作为参数传递时必须正确引用/转义，兼容空格和特殊字符路径。
  - 用户输入参数（如 `--dpi`）必须先通过 `valibot` 校验。

## UI 稳定性合同（新增）

- CLI 展示层必须使用单一进度渲染通道，不得在任务过程中混用 `console.log` 与进度条直接输出。
- 信息/警告/错误日志应通过 `progress-logger` 统一调度，确保进度 UI 不被截断或换行污染。

## 输出路径映射合同

对任意源文件 `inputRoot/rel/path/book.pdf`，目标必须映射为：

- `outputRoot/rel/path/book.cbz`

即保留 `relativePath`，仅替换扩展名，禁止跨子目录覆盖（FR-011）。
