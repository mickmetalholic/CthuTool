# Contract: CLI「运行内置脚本」子命令

## 命令语义

- **目的**：发现 `apps/cli/src/scripts` 下的有效脚本包，按用户指定或交互选择执行对应 `index.ts` 的默认导出。  
- **所属应用**：`@cthutool/cli`（Bun + Citty）。

## 调用方式（逻辑契约）

实现阶段将下列占位符替换为最终命令名与 flag 名（一旦确定，修改本文件与 `--help` 保持一致）：

1. **显式指定脚本**  
   - 用户通过**位置参数**或**选项**传入脚本 `id`（与目录名、`manifest.id` 一致）。  
   - 若 `id` 不存在：stderr 输出清晰错误，退出码非零。

2. **交互选择**  
   - 当用户**未**传入脚本 `id`，且标准输入为 TTY：展示可选列表（`title` 为主文案，`id` 为值），用户选择后执行。

3. **非交互**  
   - 当用户未传入脚本 `id` 且**非** TTY：不得阻塞等待输入；输出用法说明并非零退出。

## 与「直接用 Bun」的关系

- 用户可使用：  
  `bun run <repo-path>/apps/cli/src/scripts/<script-id>/index.ts`  
  直接执行入口，**不**经过本子命令。本子命令负责发现、校验、选择与统一错误提示。

## 帮助与可发现性

- `--help` 必须说明：子命令用途、如何指定脚本、脚本目录布局、示例（满足 spec 中「无需读源码即可理解」的验收意图）。

## 错误消息（非穷尽）

| 场景 | 预期行为 |
|------|----------|
| `scripts` 目录不存在或不可读 | Result 错误，提示检查安装/构建 |
| 无有效脚本包 | 明确提示空目录或全部无效 |
| JSON 无效或 schema 失败 | 指出包路径与校验原因 |
| 动态 import 失败 | 指出脚本 id 与可能原因 |
| 入口未提供默认导出 | 指出契约链接与修复方向 |
